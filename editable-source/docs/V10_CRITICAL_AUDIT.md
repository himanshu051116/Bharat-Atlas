# Bharat Atlas v0.10 — Critical technical audit

**Status:** Local development only. **No GitHub changes or deployments.** Existing public v0.5 remains untouched.

## Confirmed improvements

1. A reproducible **native Mapbox Vector Tile (MVT)** generator written in Python converts user-supplied, source-labelled WGS84 `LineString`/`MultiLineString` road/river layers and settlement points to sparse static XYZ `.pbf` tiles. No tile scraping and no commercial data is bundled.
2. The byte-level MVT protobuf structure is tested (layer names, feature packet, extent=4096, version=2). Generated bytes and SHA-256 metadata are deterministic for the same inputs.
3. Optional local vector detail sources are connected to MapLibre styles with zoom-dependent line and settlement layers. They are automatically hidden for user-imported administrative geometry, so unlike the previous version they cannot be visually presented as if they belong to a different imported map.
4. Core state/UT geography is **never blocked by optional tile data**. A 3-second tile metadata timeout and fallback status protect startup. The map continues in boundary-only mode when no tile dataset is available.
5. Build packaging hashes every `.pbf` and rejects corrupted or undeclared tiles. Tile metadata must explicitly deny official verification and state data licence/attribution/source. Bare GeoJSON imports do not inherit OpenStreetMap credits.
6. Browser build no longer accidentally publishes Python GIS scripts from the legacy fallback folder. Static delivery contains only legacy browser assets.
7. Tile generator refuses output paths containing input datasets and unrelated output directories to avoid destructive overwrite.

## What v0.10 does NOT solve

- No official 2026 Survey of India vector has been acquired or redistributed; northern territorial discrepancies and Shaksgam are unresolved.
- The `data/tiles/` directory is **intentionally absent** from the default public research preview. The included road/river/settlement fixtures are **fictional** and kept only under tests.
- A real MapLibre browser/WebGL renderer is NOT verified locally: MapLibre's external JS package could not be obtained in the environment, and browser smoke tests use a synthetic mock.
- This is not Google Maps-level detail: no production road network, routing, turn-by-turn navigation, live traffic, comprehensive geocoding, satellite imagery or reliable high-resolution MapLibre export.
- No actual browser tile network tests under load and no 1,000-concurrent-user evidence.
- Dataset licensing remains the user's responsibility for any additional maps.

## Reproducible steps

```bash
python -m pip install -r requirements-geo.txt
node --test tests/*.test.mjs
python -m unittest discover -s tests -p 'test_*.py' -v
python scripts/build.py
python scripts/release_guard.py --target preview
! python scripts/release_guard.py --target production
```

To exercise MVT tiles **only with the synthetic fixture**:

```bash
python scripts/build_vector_tiles.py \
  --roads tests/fixtures/roads.geojson \
  --rivers tests/fixtures/rivers.geojson \
  --settlements tests/fixtures/settlements.geojson \
  --source-metadata tests/fixtures/tile-source.json \
  --output tests/fixtures/generated --minzoom 4 --maxzoom 8
```

For a real, licensed regional layer, use `--output data/tiles` with source-specific metadata, rerun tests, build and GIS review. **Do not describe these layers as official geography.**
